# DejaVu Backend 작업 로그

작성일: 2026-07-10

## 1. 작업 개요

이번 작업에서는 Spring Boot 백엔드 초기 세팅과 인증(Auth) 기능의 기본 흐름을 구현했습니다.

주요 작업 범위는 아래와 같습니다.

- 환경설정 파일 정리
- 공통 Config 클래스 추가
- 프로젝트 구조 문서 작성
- 회원가입 API 구현
- 로그인 API 구현
- 토큰 재발급 API 구현
- 로그아웃 API 구현
- 공통 응답/예외 처리 구조 추가
- JWT 기반 인증 필터 추가

## 2. 작업 상세

### 2.1 프로젝트 기본 설정

- `application.yml` 공통 설정 정리
- `application-local.yml`, `application-prod.yml`로 프로필 분리
- `.env.example` 정리
- `README.md` 실행 방법 보강

### 2.2 공통 Config 구성

- `CorsConfig`, `CorsProperties` 추가
- `SecurityConfig` 기본 골격 추가
- `SwaggerConfig` 추가
- `PasswordEncoderConfig` 추가
- `JwtProperties` 추가
- `RestAuthenticationEntryPoint` 추가

### 2.3 공통 응답/예외 처리

- 공통 성공/실패 응답 구조 추가
- `BusinessException`, `ErrorCode`, `GlobalExceptionHandler` 추가
- 로그인, 재발급, 로그아웃 예외 코드 추가
- `ApiResponse`에서 메시지 전용 성공 응답 지원

### 2.4 회원가입 API 구현

엔드포인트:

```text
POST /api/v1/auth/signup
```

구현 내용:

- 회원 이메일 중복 검사
- 비밀번호 암호화 저장
- 희망 직무, 경력 상태, 경력 연차 저장
- 선호 기술스택을 JSON 컬럼으로 저장
- 공통 성공/실패 응답 구조 적용

추가 반영:

- ERD 기준에 맞춰 `careerYears`, `preferredSkillNames`를 nullable 허용으로 수정

### 2.5 로그인 API 구현

엔드포인트:

```text
POST /api/v1/auth/login
```

구현 내용:

- 이메일 조회
- 비밀번호 일치 여부 검증
- JWT access token 발급
- refresh token 발급
- refresh token 해시 저장
- 로그인 성공 시 사용자 기본 정보 응답

### 2.6 토큰 재발급 API 구현

엔드포인트:

```text
POST /api/v1/auth/refresh
```

구현 내용:

- 요청 받은 refresh token 해시 조회
- 토큰 존재 여부, 폐기 여부, 만료 여부 확인
- 기존 refresh token 폐기
- 새 access token / refresh token 재발급
- refresh token rotation 적용

### 2.7 로그아웃 API 구현

엔드포인트:

```text
POST /api/v1/auth/logout
```

구현 내용:

- `Authorization: Bearer {accessToken}` 검증
- 인증된 사용자와 refresh token 소유자 일치 여부 확인
- refresh token 폐기 처리
- 성공 시 `"로그아웃되었습니다."` 메시지 반환

### 2.8 JWT 인증 필터 추가

구현 내용:

- Bearer 토큰 추출
- JWT 서명 및 만료 검증
- 인증 사용자 정보 파싱
- Spring Security Context에 인증 정보 설정
- 액세스 토큰 누락/오류 시 401 JSON 응답 반환

### 2.9 프로젝트 구조 문서 작성

작성 문서:

- `docs/project-folder-structure.md`

내용:

- 현재 백엔드 패키지 구조 설명
- 도메인 패키지 역할 정리
- `common/config`와 인증 구조 설명

## 7. 확인 메모

- ERD 기준 `users.preferred_skill_names_json`은 JSON 컬럼으로 유지
- 과거 DB에 남아 있던 `user_preffered_skill` 테이블은 현재 코드 기준 사용하지 않음
- 로컬 DB 설정은 `ddl-auto: update`라서 예전 스키마 흔적은 자동 삭제되지 않음
