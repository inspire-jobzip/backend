# 2026-07-13 작업 로그_정세빈

## 채용공고 상세 조회 마무리
- `jobnotice` 패키지에 있던 `JobNotice`, `JobNoticeRepository` 역할을 `jobNotices` 패키지로 통합했다.
- `AiAnalysisService`의 `jobnotice` 참조를 `jobNotices`의 `JobNotices`, `JobNoticesRepository` 참조로 변경했다.
- 기존 JDBC class 형태의 `JobNoticesRepository`를 JPA `JpaRepository` 기반 interface로 변경했다.
- 목록/상세 조회용 native query는 Repository interface의 projection과 default method로 옮겨 기존 서비스 응답 변환 흐름을 유지했다.
- Repository interface 전환에 맞춰 서비스 테스트를 Mockito 기반으로 수정했다.
- `BackendApplicationTests`에 필요한 Repository mock을 추가해 context load 테스트를 보강했다.

## Calendar API 구현
- `feature/calendar` 브랜치를 생성하고 Calendar API 작업을 시작했다.
- `GET /api/v1/calendar/job-notices` 전체 공고 마감일정 조회 API를 추가했다.
- `GET /api/v1/calendar/bookmarks` 내 스크랩 공고 마감일정 조회 API를 추가했다.
- 연도/월 필수값과 잘못된 월 값에 대한 400 예외 처리를 추가했다.
- 내 스크랩 일정 조회는 토큰 발급/검증 기능이 아직 없어 `Authorization` 헤더 검증 위치에 JWT 연동 TODO 주석을 남기고 임시 사용자 조회 방식으로 구현했다.
- 공고 상태, 표시 문구, 남은 일수, 색상 타입 계산 로직을 추가했다.
- Calendar 서비스 단위 테스트를 추가했다.

## Calendar API 인증 연동
- 전체 공고 마감일정 조회는 비회원 공개 API로 유지했다.
- 내 스크랩 공고 마감일정 조회는 `@AuthenticationPrincipal JwtAuthenticatedUser` 기반으로 인증 사용자 ID를 사용하도록 변경했다.
- 캘린더 북마크 조회의 임시 활성 사용자 조회 로직을 제거했다.
- `/api/v1/calendar/bookmarks`는 인증 필수 경로로 지정하고 `/api/v1/calendar/job-notices`는 공개 경로로 유지했다.
- Calendar API 서비스 테스트를 인증 사용자 ID 전달 방식과 최신 응답 명세에 맞게 수정했다.

## Bookmark API 토큰 인증 연동
- 북마크 등록, 취소, 내 북마크 목록 조회에서 `Authorization` 헤더 직접 처리 로직을 제거했다.
- Spring Security의 `@AuthenticationPrincipal JwtAuthenticatedUser`를 이용해 인증 사용자 ID로 북마크를 처리하도록 변경했다.
- 북마크 API 3개 엔드포인트를 인증 필수 경로로 지정해 토큰이 없는 요청은 401 응답을 받도록 보완했다.
- 서비스 테스트를 실제 인증 사용자 ID 전달 방식에 맞게 수정했다.

## 채용공고 상세 조회 Error 응답 점검
- 상세 조회 실패 응답이 API 명세의 공통 실패 응답 구조를 따르는지 확인했다.
- 존재하지 않는 공고, 잘못된 `jobNoticeId` 형식, 서버 처리 실패 응답을 exception handler 단위 테스트로 검증했다.
