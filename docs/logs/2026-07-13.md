# 2026-07-13 작업 로그

## 채용공고 상세 조회 마무리
- `jobnotice` 패키지에 있던 `JobNotice`, `JobNoticeRepository` 역할을 `jobNotices` 패키지로 통합했다.
- `AiAnalysisService`의 `jobnotice` 참조를 `jobNotices`의 `JobNotices`, `JobNoticesRepository` 참조로 변경했다.
- 기존 JDBC class 형태의 `JobNoticesRepository`를 JPA `JpaRepository` 기반 interface로 변경했다.
- 목록/상세 조회용 native query는 Repository interface의 projection과 default method로 옮겨 기존 서비스 응답 변환 흐름을 유지했다.
- Repository interface 전환에 맞춰 서비스 테스트를 Mockito 기반으로 수정했다.
- `BackendApplicationTests`에 필요한 Repository mock을 추가해 context load 테스트를 보강했다.

## C파트 기능 고도화

### 1. 공고 기반 AI 분석 OpenAI 연동

- `OpenAiJobAnalysisClient`를 추가해 OpenAI Responses API 기반 공고 분석을 수행하도록 구현했다.
- API 키가 설정되어 있으면 OpenAI를 호출하고, 키가 없거나 호출에 실패하면 기존 규칙 기반 fallback 분석을 반환한다.
- 공고 분석 프롬프트는 개발자 채용공고 분석 목적에 맞춰 다음 항목을 JSON으로 반환하도록 구성했다.
  - 공고 전체 요약
  - 입사 후 맡게 될 업무 요약
  - 담당업무
  - 자격요건
  - 우대사항
  - 근무조건
  - 복리후생
  - 채용절차
  - 핵심 기술스택
  - 지원 판단 코멘트
  - 우대사항 한 줄 요약

관련 코드:

- `OpenAiJobAnalysisClient`
- `JobContentAnalysisService`
- `AiAnalysisService`
- `AiAnalysisResponse`

### 2. 공고 AI 분석 결과 DB 저장

- `job_notices.ai_analysis_json` 컬럼을 `JobNotice` 엔티티에 매핑했다.
- 공고 AI 분석 API 호출 시 분석 결과를 JSON으로 저장하도록 변경했다.
- 이미 분석된 공고는 저장된 `ai_analysis_json`을 우선 반환해 OpenAI를 다시 호출하지 않도록 처리했다.
- 이를 통해 같은 공고를 반복 조회할 때 비용과 응답 시간을 줄일 수 있다.

관련 코드:

- `JobNotice`
- `AiAnalysisService`

### 3. 가공 공고 데이터 추가

- 사람인 API 승인 전 테스트를 위해 OCR/수동 가공한 공고 텍스트를 DB에 넣을 수 있는 SQL을 추가했다.
- 원문 텍스트는 `description_raw`에 저장하고, 섹션별 가공 정보는 `raw_payload`와 `ai_analysis_json`에 함께 저장했다.
- Swagger에서 공고 상세 분석 및 기술스택 매핑을 테스트할 수 있는 샘플 공고 수를 늘렸다.

관련 파일:

- `mariadb-setup/06_processed_job_notice_texts.sql`
- `mariadb-setup/README.md`

### 4. 이력서 AI 피드백 OpenAI 연동

- `OpenAiResumeRecommendationClient`를 추가해 공고와 이력서를 비교한 AI 피드백을 생성하도록 구현했다.
- AI에게 전달하는 정보는 다음과 같다.
  - 공고 기본 정보 및 원문
  - 공고 기술스택
  - 이력서 기본 정보
  - 이력서 기술스택
  - 이력서 프로젝트 경험
  - 공고-이력서 일치 키워드
  - 부족 키워드
  - Jaccard 유사도
- 응답은 이력서 보완 피드백, 추천 프로젝트 제목, 추천 프로젝트 설명으로 구성했다.

관련 코드:

- `OpenAiResumeRecommendationClient`
- `AiAnalysisService`
- `AiRecommendationResponse`

### 5. 이력서 AI 피드백 DB 저장 및 목록 조회

- `ai_recommendations` 테이블과 연결되는 `AiRecommendationEntity`를 추가했다.
- `AiRecommendationRepository`를 추가해 AI 피드백 기록을 DB에서 조회할 수 있도록 했다.
- `POST /ai-recommendations` 호출 시 생성된 피드백을 DB에 저장하도록 변경했다.
- `GET /ai-recommendations` 호출 시 메모리 데이터가 아니라 DB에 저장된 피드백 목록을 반환하도록 변경했다.

관련 코드:

- `AiRecommendationEntity`
- `AiRecommendationRepository`
- `AiAnalysisService`

### 7. 남은 개선 사항

- 현재 일부 C파트 기능은 MVP 테스트를 위해 임시 `userId = 1` 기준으로 동작하므로, 로그인/JWT 인증과 연결해야 한다.
- 프론트엔드 공고 상세 화면에서 공고 AI 분석 결과를 표시하도록 연결해야 한다.
- 프론트엔드 이력서 화면에서 이력서 CRUD와 프로젝트 CRUD를 연결해야 한다.
- 프론트엔드에서 이력서 AI 피드백 생성 및 목록 조회 화면을 연결해야 한다.
- 공고 분석 프롬프트는 화면 표시용으로 더 짧고 일관된 문장 구조가 나오도록 고도화가 필요하다.
- 이력서 피드백 프롬프트는 신입/경력, 직무별로 다른 조언이 나오도록 개선할 수 있다.
- 실제 사람인 API 연동 후 API 응답 데이터와 OCR/이미지형 공고 텍스트 처리 방식을 확정해야 한다.
- 컨트롤러/서비스 단위 테스트와 AI fallback 테스트를 추가해야 한다.
