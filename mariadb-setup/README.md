# Dejavu MariaDB Setup

This folder contains the MariaDB setup files for the Dejavu MVP.

## Files

| File | Purpose |
|---|---|
| `01_schema.sql` | Creates the `dejavu` database and all 9 ERD tables |
| `02_seed_skills.sql` | Inserts default skill master data |
| `03_sample_data.sql` | Optional sample user, job notice, bookmark, resume, and project |
| `04_common_queries.sql` | Useful queries for checking API implementation |
| `05_sample_saramin_job_notices.sql` | Optional Saramin HTML archive sample job notices |
| `06_processed_job_notice_texts.sql` | Optional processed job notice text data from HTML/OCR extraction |
| `07_saramin_it_job_notices_20260715.sql` | Optional live-crawled Saramin IT job notice seed data |
| `08_saramin_it_job_notices_cleaned_20260715.sql` | Cleaned Saramin IT/data job notice seed data |
| `09_saramin_it_job_notices_cleaned_20_20260715.sql` | Curated 20-row Saramin IT/data seed data with OCR text cleanup |
| `collect_saramin_it_job_notices.py` | Collects first-pass Saramin IT job notice candidates |
| `enhance_saramin_it_job_notices_with_ocr.py` | Adds OCR text from image-based Saramin detail pages |
| `ocr_saramin_images.js` | Node helper used by the OCR enhancement script |
| `create_cleaned_saramin_it_job_notices.py` | Restores noisy Korean text and removes non-IT notices from `07` |
| `create_cleaned_20_saramin_it_job_notices.py` | Builds the curated 20-row SQL from `08` |

## Recommended MariaDB Version

- MariaDB 10.6+
- Character set: `utf8mb4`
- Collation: `utf8mb4_unicode_ci`

## Run Order

From this folder:

```bash
mysql -u root -p < 01_schema.sql
mysql -u root -p < 02_seed_skills.sql
mysql -u root -p < 03_sample_data.sql
mysql -u root -p < 05_sample_saramin_job_notices.sql
mysql -u root -p < 06_processed_job_notice_texts.sql
mysql -u root -p < 07_saramin_it_job_notices_20260715.sql
mysql -u root -p < 08_saramin_it_job_notices_cleaned_20260715.sql
mysql -u root -p < 09_saramin_it_job_notices_cleaned_20_20260715.sql
```

The sample data files are optional. Use them only for local development checks.
Use only one Saramin seed file at a time. Prefer `09` when a smaller, hand-curated IT/data dataset is enough for local development.

## Saramin OCR Enhancement

Some Saramin detail pages store the job description as images. To regenerate OCR-enhanced detail text for `07_saramin_it_job_notices_20260715.sql`, prepare a temporary Node runtime and run the enhancer from the backend root:

```bash
mkdir %TEMP%\saramin-ocr-node
cd %TEMP%\saramin-ocr-node
npm init -y
npm install tesseract.js@7.0.0 --no-audit --no-fund
cd C:\Inspire\project\backend
python mariadb-setup\enhance_saramin_it_job_notices_with_ocr.py
```

If Node is installed somewhere else, set `SARAMIN_OCR_NODE_PATH`. If the OCR runtime is installed in another folder, set `SARAMIN_OCR_NODE_DIR`.

To regenerate the cleaned SQL from the OCR-enhanced SQL:

```bash
python mariadb-setup\create_cleaned_saramin_it_job_notices.py
```

To regenerate the curated 20-row SQL:

```bash
python mariadb-setup\create_cleaned_20_saramin_it_job_notices.py
```

## Docker Option

If MariaDB is not installed locally, run:

```bash
docker compose up -d
```

This starts MariaDB 10.11 and automatically runs:

1. `01_schema.sql`
2. `02_seed_skills.sql`

Default connection values:

| Key | Value |
|---|---|
| Host | `localhost` |
| Port | `3306` |
| Database | `dejavu` |
| Username | `dejavu` |
| Password | `dejavu1234` |

If you already have a local MariaDB on port `3306`, change the left side of the port mapping in `docker-compose.yml`, for example `"3307:3306"`.

## Backend Connection Example

```properties
spring.datasource.url=jdbc:mariadb://localhost:3306/dejavu?useUnicode=true&characterEncoding=utf8
spring.datasource.username=dejavu
spring.datasource.password=dejavu1234
spring.datasource.driver-class-name=org.mariadb.jdbc.Driver
```

## Notes

- The API uses `camelCase`, but database columns use `snake_case`.
- JSON fields are kept as MariaDB `JSON` columns for MVP speed.
- `skills` is a master table and should not be deleted casually.
- `job_notice_skills` is generated by matching Saramin title/job-code/keyword text against `skills.skill_name`.
- `bookmarks + job_notices.deadline_at` is enough for the MVP calendar.
- `users -> resumes -> resume_projects` uses `ON DELETE CASCADE`, so deleting a user removes their resume data.
- Some Saramin postings put duties, qualifications, and preferences inside images. In that case, keep the OCR result in `description_raw` and store image-level extraction details in `raw_payload.ocrTexts`.
