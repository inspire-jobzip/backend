# Dejavu MariaDB Setup

This folder contains the MariaDB setup files for the Dejavu MVP.

## Files

| File | Purpose |
|---|---|
| `01_schema.sql` | Creates the `dejavu` database and all 9 ERD tables |
| `02_seed_skills.sql` | Inserts default skill master data |
| `03_sample_data.sql` | Optional sample user, job notice, bookmark, resume, and project |
| `04_common_queries.sql` | Useful queries for checking API implementation |
| `05_sample_saramin_job_notices.sql` | Optional Saramin HTML archive sample job notices |
| `06_processed_job_notice_texts.sql` | Optional processed job notice text data from HTML/OCR extraction |

## Recommended MariaDB Version

- MariaDB 10.6+
- Character set: `utf8mb4`
- Collation: `utf8mb4_unicode_ci`

## Run Order

From this folder:

```bash
mysql -u root -p < 01_schema.sql
mysql -u root -p < 02_seed_skills.sql
mysql -u root -p < 03_sample_data.sql
mysql -u root -p < 05_sample_saramin_job_notices.sql
mysql -u root -p < 06_processed_job_notice_texts.sql
```

The sample data files are optional. Use them only for local development checks.

## Docker Option

If MariaDB is not installed locally, run:

```bash
docker compose up -d
```

This starts MariaDB 10.11 and automatically runs:

1. `01_schema.sql`
2. `02_seed_skills.sql`

Default connection values:

| Key | Value |
|---|---|
| Host | `localhost` |
| Port | `3306` |
| Database | `dejavu` |
| Username | `dejavu` |
| Password | `dejavu1234` |

If you already have a local MariaDB on port `3306`, change the left side of the port mapping in `docker-compose.yml`, for example `"3307:3306"`.

## Backend Connection Example

```properties
spring.datasource.url=jdbc:mariadb://localhost:3306/dejavu?useUnicode=true&characterEncoding=utf8
spring.datasource.username=dejavu
spring.datasource.password=dejavu1234
spring.datasource.driver-class-name=org.mariadb.jdbc.Driver
```

## Notes

- The API uses `camelCase`, but database columns use `snake_case`.
- JSON fields are kept as MariaDB `JSON` columns for MVP speed.
- `skills` is a master table and should not be deleted casually.
- `job_notice_skills` is generated by matching Saramin title/job-code/keyword text against `skills.skill_name`.
- `bookmarks + job_notices.deadline_at` is enough for the MVP calendar.
- `users -> resumes -> resume_projects` uses `ON DELETE CASCADE`, so deleting a user removes their resume data.
